# 评分算法与数据口径

本页对应当前生产代码。工具分别输出角色六星、当期 UP、限定、角色五星、六星武器、当期专武六项分数，不计算六维均分。分数通常在 0—100，越高表示在该项参照模型下产出越好。

这些分数采用不同参照。它们不代表全体真实玩家的排名，也不保证不同停手策略的平均分都是 50。

## 计算方法概览

| 项目 | 当前方法 | 需要注意 |
| --- | --- | --- |
| 角色六星 | 普通 80 保底的总六星数量 DP，加急数量分布卷积 | 实际 120 强制六星计入产出，参照不额外加入 120 收益 |
| 当期 UP | 已出货等待时间 DP 与卷积，再按抽数合并已出、未出、加急分数 | 最终是加权指数，不是一个联合分布的百分位 |
| 限定 | 普通 80 保底、限定价值及持有图鉴的 DP | 缺失历史采用单独的兼容分支，结果中明确标识 |
| 角色五星 | 固定基准、离线样本校准与正态映射 | 不是针对当前记录逐次运行的精确数量 DP |
| 武器，未填潜能修正 | 固定完成 10 个首专武池的产出率分布 DP | 参照投入是随机变量，不是固定实际抽数 |
| 武器，已填潜能修正 | 各目标份数的终止均值、协方差 DP，再作正态近似 | 终止矩由 DP 计算，最终产出率分位为近似 |
| 规划亏损 | 逐池停点比较、固定水位价值表及局部机会估值 | 单位是抽，不是欧非分或整账号最优策略证明 |

角色评分入口是 [`character_score.js`](../tools/gacha_rating_app/character_score.js)，应用编排入口是 [`service.py`](../tools/gacha_rating_app/service.py)。

## 角色规则与统计范围

当前目录包含从“熔火灼痕”到“烟火邀星河”的 13 个常规限定池，最后一期 UP 为明河。目录与可出角色由 [`importer.py`](../tools/gacha_rating_app/importer.py) 和 [`character_ledger.js`](../tools/gacha_rating_app/character_ledger.js) 定义。复刻、庆典、常驻记录不能直接混进这套常规限定参照。

- 六星基础概率为 0.008。此前连续未出六星数为 `p` 时，下一抽的概率在 `p < 65` 时为 0.008；从第 66 抽起每抽增加 0.05，第 80 抽必出。六星出货重置该水位，常规限定池之间继承水位。
- 单池前 120 主抽内尚无主池当期 UP 时，第 120 抽强制取得当期 UP；此前取得主池 UP 则该次保障失效。它不免除更早触发的 80 抽六星保障。
- 独立加急十连通常在主池第 30 抽后使用，也允许记录实际使用时点。它不推进或重置主池水位；各抽六星概率为 0.008，当期 UP 概率为 0.004。
- 每 240 主抽的信物单列，不计抽数、角色随机六星、角色 UP 或限定轴产出。规划模块可以将信物视为有效收获。
- 限时免费主抽属于主池抽数，与独立加急十连不同。

### 角色六星

把每段期初水位已知的连续主池记录汇总为投入 `N` 与六星数 `K`。DP 状态为“已出六星数、水位”，递推普通 80 保底下的数量分布。实际记录里的 120 强制六星与其他六星等权计入 `K`，末尾未出段也计入 `N`。

独立加急的六星数服从 `Binomial(加急抽数, 0.008)`。各主池连续段与加急的分布卷积后，按实际总六星数计算中位分位。

```text
Score6 = 100 × [P(K参照 < K实际) + 0.5 × P(K参照 = K实际)]
```

这里选择把能获得的 120 规则收益体现在实际产出中。因此，长期追潜与经常吃到首次 120 保障的记录，分数分布可能不同。实现见 [`character_six_count.js`](../tools/gacha_rating_app/character_six_count.js)。

### 当期 UP

从上一个主池 UP 到下一个主池 UP 合并全部等待，包括中间换池和歪出的六星。每段参照的 120 截止位置由实际出货所在池确定。例如 A 池垫 60 抽，B 池第 20 抽出 UP，则实际等待为 80，参照截止位置为 180；不模拟尚未发生的后续换池选择。同池首 UP 后的追潜段没有首次 120 保障。

对各已完成段计算下一 UP 的等待时间分布，卷积后比较已完成总耗抽 `C`。

```text
已出货分 Sc = 100 × [P(T参照 > C) + 0.5 × P(T参照 = C)]
未出段分 Su = 50 × P(抽到该段当前长度仍没有 UP)
```

加急按全部加急抽数的 `Binomial(加急抽数, 0.004)` 计算 UP 数量中位分位 `Sr`。加急 UP 不结束主池等待。

```text
UP分 = (已出货抽数 × Sc + 未出抽数 × Su + 加急抽数 × Sr)
       / 全部可确认主池与加急抽数
```

有历史断点时，断点前尚未完成的等待也作为未出段处理，分别按长度计入权重。信物既不结束等待，也不计 UP。实现见 [`character_up_dp.js`](../tools/gacha_rating_app/character_up_dp.js)。

### 限定

实际和参照使用同一价值规则：常驻角色为 0，限定角色为 1，歪出的未持有限定角色为 2；当期 UP 即使首次取得也为 1。信物为 0。

参照使用普通 80 保底，状态包含水位、累计价值和相关限定持有集合。每次六星当期 UP 的概率为 `7/14`，两名可歪限定各 `1/14`，常驻合计 `5/14`。每个分支各自更新图鉴，加急更新图鉴及价值而不改变主池水位。对总价值使用与六星轴相同的中位分位公式，最高 100 分。

期初图鉴未知但水位已知、历史连续时，实际与参照都关闭 New 倍权。期初水位未知、缺少中间卡池或使用中断修正时，路由到 `partial-history-limited-compatibility-dp`，保留可确认的完整六星周期和身份价值；这与完整历史的总产出分布口径不同。实现见 [`character_limited_count.js`](../tools/gacha_rating_app/character_limited_count.js) 与 [`character_result_score.js`](../tools/gacha_rating_app/character_result_score.js)。

### 角色五星

先用同一统计范围的武库配额反推五星数。设总抽数为 `T`，六星数为 `K6`，配额为 `Q`。

```text
F = (Q - 20 × T - 1980 × K6) / 180
```

不能反推出合法整数时，五星轴显示数据不足或冲突，不猜填。

设主抽数为 `N`，独立加急十连的次数为 `R`，则 `T = N + 10R`。当前基准为：

```text
E = 0.13411295200285397 × N + 1.1980598575793349 × R
p = E / N
z = (F - E) / sqrt(N × p × (1-p))
五星分 = 100 × Φ((z - μ) / σ)
μ = -0.08096081491239257
σ = 0.5754562752790213
```

`Φ` 是标准正态累积分布函数。`μ`、`σ` 来自固定参照策略的 2000 条离线模拟记录校准，评分时只读取冻结参数，不重新抽样。原校准使用 11 期参照策略，当前 13 池目录沿用这些参数。这是近似参照，不能称为逐账号条件 DP 的精确期望。实现及参数见 [`scorer.js`](../tools/character_five_score/scorer.js) 与 [`parameters.json`](../tools/character_five_score/parameters.json)。

## 武器两轴

原始输入 `N / K6 / KU` 分别为实际武器抽数、抽出的六星武器数、抽出的当期专武数。40 抽六星及首次 80 抽专武保障的出货计入原始产出，直接赠送的武器不计入这些原始数量。模型采用六星概率 0.04、六星为当期专武的概率 0.25。

未填写潜能配置时，参照固定完成 10 个从零开始的首专武池，每池在首次专武所在十连结束时停手。计算总抽数与产出数量的联合分布，再比较产出率。该参照的池数固定为 10，不从上传记录的池数自动推断。

填写潜能配置后，每种专武的实际总份数成为一个参考目标。0 潜是 1 份，5 潜是 6 份，溢出继续加在所属武器上。参照每池从零开始，达到“直接出货＋180、340、500……节点直赠”的目标后结算完整十连。多种满潜武器有溢出时，需要分别分配份数。

DP 计算终止时的抽数、六星数、专武数的均值与协方差。令实际产出率为 `r`，参照残差为 `K - rN`，最终用正态近似映射分数。两项产出在此模式下均加入直赠；直赠数量由“配置总份数减去原始 KU”推算，要求统计范围一致，不是逐条赠品验证。未知武库箱内容不应擅自计为某件专武。

可选 `lossDraws` 只从当期专武轴的实际分母中扣除，六星武器轴仍使用全部实际抽数。旧平均耗抽字段不参与评分。实现见 [`weapon_scoring.py`](../tools/gacha_rating_app/weapon_scoring.py)、[`ten_pool_reference.py`](../tools/weapon_score_v2/ten_pool_reference.py) 与 [`potential_profile_score.py`](../tools/weapon_score_v2/potential_profile_score.py)。

结果目标不等于玩家事先的抽取意图。这个参照不能还原试水、未完成池、期初库存、复刻继承和实际停手方式；潜能模式也不是精确产出率分位。

## 规划亏损

规划单独展示“资源损耗”和“机会估值”，两者不相加，也不合成六维分数。

资源损耗以每池最后有效收获为参考，包括主池 UP、加急 UP、信物及可确认的歪 New 限定；参考停点至少用完本池免费额度，收获在第 46—59 抽时参考补至 60。没有有效收获时以免费额度为停点。比较永久抽消耗、水位价值和 60 节点下期赠券价值：

```text
逐池损耗 = 永久抽消耗差 - 水位价值差 - 赠券价值差
```

水位价值读取随代码发布的固定表，不在评分时模拟或外推。逐池保留正负结果；选择豁免时只免除该池的正损耗，保留收益。

机会估值比较“本池继续获取首 UP”和“换到下一池获取首 UP”的条件期望净成本，使用有限 DP 与同一终态资源价值表。它没有单独定价未来歪 New 或额外潜能，是局部机会估值。实现见 [`planning.py`](../tools/gacha_rating_app/planning.py)、[`opportunity.py`](../tools/gacha_rating_app/opportunity.py) 与 [`water_values.json`](../tools/gacha_rating_app/water_values.json)。

## 输入、修正与输出

内部账本版本是 `gacha-ledger-v1`。网页可恢复包含来源、账本和设置的 `gacha-rating-session-v1` 文件，也可通过 `record_import.py` 将已适配的批次 TXT/JSON、接口列表、internal_json_v3 和 EndUID 导出转换为账本。稀有度编码按源格式解释，加急与赠品单列；来源原文、原始条目和无法确认的信息一同保留。它不是任意第三方 JSON 的通用读取器。

序号缺口使用明确的导入约定：在池起点和累计主抽位置可确认、此前没有未解释缺口的范围内，已知奖励节点恰缺 1 条且没有对应奖励条目，按漏导赠品处理。角色限定池第 60 抽对应赠券、240 的整数倍对应信物；武器池第 100 抽起每 80 抽对应交替的武库箱与专武直赠。原始条目保持原样，推断单独标记；不增加实际抽数、抽出的六星、随机 UP 或配额，不重复增加已计入的奖励。其他位置、连续缺多条或起点不确定时，仍保留待核对信息。

| 字段 | 含义 |
| --- | --- |
| `character.pools` | 按池序号递增的常规限定池列表 |
| `pool.index / banner / up` | 目录序号、池名和当期 UP，当前序号为 0—12 |
| `pool.total` | 本池主抽数，包含免费主抽，不包含独立加急 |
| `pool.events[].at` | 本池从 1 开始的主抽累计出货位置，不是相邻出货间隔 |
| `pool.events[].character` | 实际出货角色，`source` 为 `main` |
| `pool.initialPity / tail` | 本池期初、期末连续未出六星数；未知使用 `null` |
| `pool.rushUsed / rushAt / rush` | 是否使用加急、使用时的主池进度、加急六星明细 |
| `pool.tokens` | `at` 为 240 整数倍的信物节点列表 |
| `pool.quota` | 与主池及已用加急范围一致的配额产出 |
| `character.initialOwned` | 首池之前已持有角色列表，`null` 表示未知，空列表表示已确认无持有 |
| `character.completeHistory` | 是否确认导入范围的连续历史，不能用来掩盖实际缺失记录 |
| `weapon.potentialConfig` | `totalTypes`、1—5 潜的 `counts`、`overflowCopies`、各满潜的 `overflowByType` |
| `weapon.lossDraws` | 专武分母中扣除的可选亏损抽数 |

应用先重校验账本再评分。原图、OCR 标注和来源证据保留；手动补抽会更新当前及后续连续记录的派生水位，旧截图“已垫”不作为独立游戏状态锁死。人工明确填写的水位与真实 80／120 规则矛盾仍需要处理。

中断修正通过 `character.interruptionCorrection` 排除选定角色池，后续首个保留池从零水位及所选免费额度重启，不补造丢失出货，不改变武器范围。它会改变有效评分范围。

“假设补到保底”保存为独立的 `scoringScenario`。启用时六维结果和规划使用派生的假设记录，实际账本保持原样；关闭后恢复实际记录。不能把假设结果作为真实抽卡事实重新导入。

每个轴返回 `score`、`status` 和 `details` 或 `reason`。信息不足时 `score` 为 `null`，不自动给 0 或 50。诊断中应同时检查 `scoredAxes`、缺失原因、有效抽数及兼容分支标记，不能只看雷达图是否画出了形状。

## 版本与数值边界

| 模块 | 版本 |
| --- | --- |
| 角色评分 | `character-count-merged-up-v5-catalog-20261105` |
| 五星 | `five-flat-v1` |
| 武器输入及路由 | `weapon-potential-table-loss-v2-20261104` |
| 武器潜能模型 | `weapon-result-profile-gift-inclusive-normal-1.0` |
| 规划 | `planning-stopped-pools-v2.3-20261104` |
| 识别证据及账本校验 | `card-boundary-review-v7-pity-source-20261109` |

这里的“精确 DP”指所定义离散参照模型中的确定性递推，仍使用浮点计算。较长卷积使用 FFT；分位计算只保存所需的概率前缀，上尾被截去后不重新归一化。代码设有规模和运行时间上限，超限会报告缺项。

OCR 的结果需要通过身份、总数、位置及机制校验；支持的截图结构不等于所有设备版式都已验证。旧实验文件或兼容模块中的公式不能替代当前入口。更改目录、规则、参照策略或校准参数时，应同时更新版本、对应测试与本说明。
